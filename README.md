# PlacementPrep AI

PlacementPrep AI is a career and interview preparation platform for students. It combines a resume
analyzer, an interview practice tool, and a job-application tracker in one dashboard, so you can
manage your placement season in one place.

This is a full-stack project: a React (Vite) frontend talking to a Flask REST API backed by MySQL.

## Features

- **Authentication** — register/login with hashed passwords (bcrypt) and JWT-based sessions. All data is scoped to the logged-in user.
- **Dashboard** — real stats pulled from the database: latest resume score, total applications, applications by status, interview session count, and recent activity.
- **Resume Analyzer** — upload a PDF resume; the backend extracts the text and returns a score (0–100), detected skills, strengths, weaknesses, and suggestions. This is an **application-generated score, not an official ATS score**.
- **Interview Preparation** — pick a role, topic, and difficulty, get a question, write an answer, and receive a score with strengths and improvement tips. Sessions are saved to your history.
- **Application Tracker** — full CRUD for job applications (company, title, date, status, URL, notes), with status filtering.
- **Profile** — edit your name, email, target role, and skills.
- **AI integration with a real fallback** — if you provide an `ANTHROPIC_API_KEY`, resume analysis, question generation, and answer feedback are generated by Claude. If you don't, PlacementPrep AI automatically falls back to a built-in rule-based resume analyzer and a local interview question bank, so the app is fully usable either way. Every result is labeled `ai` or `rule_based` so you always know which one produced it.

## Technology Stack

**Frontend:** React, Vite, React Router, plain CSS (no UI framework)
**Backend:** Python 3, Flask, Flask-CORS, Flask-JWT-Extended, Flask-SQLAlchemy
**Database:** MySQL
**Other:** bcrypt (password hashing), pypdf (PDF text extraction), python-dotenv (env vars)

## Prerequisites

- Python 3.10+ (built and tested with Python 3.12; Python 3.14 as originally specified works the
  same way — just make sure `pip` and `venv` are available for whichever version you install)
- Node.js 18+ and npm
- MySQL Server 8.0+ (running locally, or accessible via host/port)

## Installation

### 1. Clone / open the project

Open the `placementprep-ai` folder in your editor (e.g. VS Code).

### 2. Backend setup

```bash
cd backend
python3 -m venv venv

# Activate the virtual environment
# macOS/Linux:
source venv/bin/activate
# Windows:
venv\Scripts\activate

pip install -r requirements.txt
```

Copy the example environment file and fill in your own values:

```bash
cp .env.example .env
```

Edit `backend/.env`:

```
SECRET_KEY=<generate a long random string>
JWT_SECRET_KEY=<generate a different long random string>

DB_HOST=localhost
DB_PORT=3306
DB_NAME=placementprep_ai
DB_USER=root
DB_PASSWORD=<your MySQL password>

MAX_UPLOAD_MB=5
FRONTEND_ORIGIN=http://localhost:5173

# Optional — leave blank to use the built-in rule-based fallback
ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=claude-sonnet-4-6
```

You can generate random secret strings with:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### 3. MySQL setup

Make sure MySQL Server is running, then create the database and tables with the included script
(it connects using the credentials in your `.env` and creates the database if it doesn't exist):

```bash
cd backend
python init_db.py
```

You should see:
```
Database 'placementprep_ai' is ready.
All tables created successfully.
```

If you'd rather create the database manually, the equivalent SQL is:

```sql
CREATE DATABASE IF NOT EXISTS placementprep_ai CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
— then run `python init_db.py` again to create the tables (it skips database creation if it
already exists).

### 4. Frontend setup

```bash
cd frontend
npm install
cp .env.example .env
```

`frontend/.env` should point at your backend (default is fine for local development):

```
VITE_API_URL=http://localhost:5000/api
```

## Running the Application

You need **two terminals** running at the same time.

**Terminal 1 — backend:**
```bash
cd backend
source venv/bin/activate   # Windows: venv\Scripts\activate
python run.py
```
The API runs at `http://localhost:5000`.

**Terminal 2 — frontend:**
```bash
cd frontend
npm run dev
```
The app runs at `http://localhost:5173`. Open that URL in your browser.

## Using the Application

1. **Register** a new account at `/register` (password needs 8+ characters with at least one letter and one number).
2. You'll land on the **Dashboard**, which starts empty — that's expected for a new account.
3. Go to **Resume Analyzer**, upload a PDF resume, and review your score, detected skills, and suggestions.
4. Go to **Interview Prep**, pick a role/topic/difficulty, answer the generated question, and read your feedback.
5. Go to **Applications** to add companies you've applied to and move them through statuses (Saved → Applied → Assessment → Interview → Offer/Rejected).
6. Go to **Profile** to set your target role and skills.
7. Return to the **Dashboard** — it now reflects your real activity.

## Environment Variables Reference

**Backend (`backend/.env`):**

| Variable | Required | Description |
|---|---|---|
| `SECRET_KEY` | Yes | Flask session secret |
| `JWT_SECRET_KEY` | Yes | Secret used to sign JWTs |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Yes | MySQL connection details |
| `MAX_UPLOAD_MB` | No (default 5) | Max resume upload size |
| `FRONTEND_ORIGIN` | Yes | Used for CORS, e.g. `http://localhost:5173` |
| `ANTHROPIC_API_KEY` | No | If set, enables AI-powered analysis/feedback |
| `ANTHROPIC_MODEL` | No | Defaults to `claude-sonnet-4-6` |

**Frontend (`frontend/.env`):**

| Variable | Required | Description |
|---|---|---|
| `VITE_API_URL` | Yes | Base URL of the backend API |

Never commit real `.env` files — only `.env.example` files are tracked in git.

## Known Limitations

- **No AI key by default.** Without `ANTHROPIC_API_KEY`, resume analysis and interview feedback use
  the built-in rule-based logic instead of an LLM. This is intentional (not a bug) — the app is
  fully functional either way, and every result is labeled so you know which mode produced it.
- **Scanned/image-only PDFs** aren't supported — text extraction requires a PDF with a real text
  layer, not a photo or scanned image of a resume.
- **Single JWT session, no refresh token flow.** Tokens are valid for 7 days; there's no "remember
  me" vs. short session distinction, and no refresh-token rotation. This is a deliberate
  simplification appropriate for a student project, not something you'd want in production as-is.
- **No email verification or password reset flow.** Registration is immediate; there's no email
  step, since no email-sending service is configured.
- **No automated test suite is included** (e.g. pytest/Jest files); the backend was verified with
  manual end-to-end HTTP testing covering every route, and the frontend was verified with a
  production build.
